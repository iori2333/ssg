# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build

```bash
# Prerequisites: Visual Studio 2022+, Git, CMake 3.21+, Ninja

# Windows (from x64_x86 Cross Tools Command Prompt, or just run the .bat)
./build_windows.bat                    # full Release build

# Linux
./build_linux.sh                       # full Release build

# Manual CMake (alternative to the scripts above)
cmake -B build -S . -G "Ninja" -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

# Debug build
cmake -B build -S . -G "Ninja" -DCMAKE_BUILD_TYPE=Debug
cmake --build build --config Debug

# Output: build/bin/GIAN07.exe (Windows) or build/bin/GIAN07 (Linux)
```

VS Code's `Ctrl-Shift-B` runs the CMake configure + build task. The `.vscode/tasks.json` has separate tasks for Debug/Release configure and build.

## Architecture

This is a C++23 re-engineering of **秋霜玉** (Shuusou Gyoku), a Windows STG (shooting game) originally written ~2000 by pbg. The codebase has a three-layer architecture:

### Layer 1: `GIAN07/` — Original game code
The original pbg code, modernized in place. Uses 8.3 filenames with `.CPP` extensions (historical PC-98 carryover). Defines game entities (players, enemies, bullets, bosses), the ECL scripting system (enemy control language), config system, and game flow. Includes via `#include` from the `GIAN07/` directory. Key entry points:
- `main()` in `platform/sdl/main.cpp` calls `XInit()`, then `WndBackend_Run()`
- `WndBackend_Run()` (in `platform/sdl/window_sdl.cpp`) runs the main loop, calling `GameFrame()` each iteration
- `GameFrame()` (in `GIAN07/ENTRY.cpp`) handles global hotkeys, then invokes `GameMain` — a function pointer to the current game state (menu, gameplay, ending, etc.)

### Layer 2: `game/` — Platform-independent abstractions
Pure C++ game infrastructure with no system calls. Provides graphics primitives (`graphics.h` with palettes, surfaces, geometry), audio (`bgm.h`, `midi.h`, `snd.h`), input (`input.h`), text rendering (`text.h`, `text_packed.h`), coordinate systems (`coords.h`), math (`ut_math.h`), pixel formats (`pixelformat.h`). Also contains codec loaders in `game/codecs/` (FLAC, Vorbis). Code here may include from the top level of `platform/` but not from subdirectories.

### Layer 3: `platform/` — OS backends
Platform-specific implementations. Game code should only include headers from `platform/` itself, not from subdirectories:

| Directory | Role | Platform |
|-----------|------|----------|
| `platform/sdl/` | SDL3 window, graphics, input, filesystem, threads | Both |
| `platform/miniaudio/` | Audio via miniaudio single-header (`miniaudio.c`) | Both |
| `platform/windows/` | Win32 GDI text, WinMM MIDI, surface, file I/O | Windows |
| `platform/c/` | POSIX file I/O, time, threads | Linux |
| `platform/pangocairo/` | Text rendering via PangoCairo | Linux |

Key abstraction interfaces defined as headers in `platform/`: `graphics_backend.h`, `window_backend.h`, `text_backend.h`, `midi_backend.h`, `snd_backend.h`, `file.h`, `input.h`, `time.h`, `path.h`.

### Coordinate systems (defined in `game/coords.h`)
- **Pixel space** (`PIXEL_*`): Unscaled output space, relative to any origin
- **Window space** (`WINDOW_*`): Game window at native 640×480 (`GRP_RES`). Visible area (0,0)–(639,479)
- **World space** (`WORLD_*`): Subpixel-precise game coordinates, `WORLD_COORD` = `PIXEL_COORD << 6` (6 bits subpixel precision)

### Main loop
```
platform/sdl/main.cpp::main()
  → XInit()           (GIAN07/ENTRY.cpp — init config, graphics, audio, input)
  → WndBackend_Run()  (platform/sdl/window_sdl.cpp — SDL event pump + frame timer)
    → GameFrame()     (GIAN07/ENTRY.cpp — global hotkeys, then forwards to...)
      → GameMain()    (function pointer set to current screen: menu, gameplay, etc.)
  → XCleanup()        (cleanup subsystems)
```

### Libraries (`libs/`, git submodules)
SDL3, BLAKE3, libogg, libvorbis, libwebp — built as static libs. `dr_libs` is header-only. `miniaudio` is compiled via `platform/miniaudio/miniaudio.c` as C++.

## Important constraints

- **C++23**, C++20 Modules **removed** — CMake does not enable modules
- **No vintage/Win98 paths** — All `WIN32_VINTAGE`, `__WIN9X__` code and `platform/windows_vintage/` have been removed
- **Windows primary** (MSVC), Linux is secondary and may need system packages (pangocairo, fontconfig)
- **Static CRT** on Windows (`MultiThreaded`/`MultiThreadedDebug`) to match static SDL3
- **Generated headers** in `obj/`: `version.h` and `platform_constants.h` are generated by CMake at configure time from git info and `APP_ID`/`PATH_SKELETON` environment variables. Do not edit these directly.
- **No tests** for the project code — there is no test infrastructure; only vendored submodules contain their own test suites
- **Formatting**: LLVM-based `.clang-format` at the repo root
- **`.CPP` extension**: The original GIAN07 code uses uppercase `.CPP` for C++ files. New code in `game/` and `platform/` uses lowercase `.cpp`.
- **`PBG_DEBUG`**: Conditional debug compilation flag used in original code (not a CMake build type)
- **Narrowing utilities**: `game/narrow.h` provides `narrow()` and `narrow_size_t()` for safe integer narrowing — prefer these over C-style casts
- **`game/defer.h`**: Provides a `defer()` macro (RAII-style cleanup) — the codebase uses this instead of `finally` or scope guards
- **`game/cast.h`**: Provides `enum_val()` for safe enum-to-underlying conversions, preferred over `static_cast`/`std::to_underlying` in this codebase

## Code guidelines

- **Compilation**: After making changes, ensure the project compiles successfully. Run the appropriate build command for the current platform (see [Build](#build) above).
- **Git safety**: Never run destructive git commands (`git reset --hard`, `git clean -fd`, `git push --force`, etc.) unless explicitly instructed by the user.
- **Include order**: Follow the standard C++ convention — standard library headers first (`<cstdint>`, `<vector>`, etc.), then third-party/system headers (`<SDL3/...>`, `<windows.h>`, etc.), then project headers (`"game/..."`, `"platform/..."`, etc.). Within each group, sort alphabetically. For conditional includes (e.g., `<windows.h>` inside `#ifdef WIN32`), the same ordering applies within the conditional block.
- **Formatting**: After making changes, format the modified code with clang-format. The project uses an LLVM-based `.clang-format` at the repo root. Run `clang-format -i <file>` on each changed file.
